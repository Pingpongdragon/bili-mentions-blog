从模型到 Harness：Agent 上下文工程与驾驭工程的 100 分钟

UP：xiegangqingn_com · BV1N7bv6SEht · 2026-11-12

一句话总结模型只是无状态文字函数；工具/MCP/skill/plugin 决定能做什么，上下文五操作（写入/选择/检索/压缩/隔离）与 harness 五层决定稳不稳；独立验收与验证标准比让 Agent 跑起来更难。

一句话总结

这场 100 分钟直播把 Agent 拆成三层：模型只是无状态的“文字函数”，工具/MCP/skill/plugin 决定它能做什么，上下文工程与 harness 决定它做得稳不稳；最后落到“循环工程”——真正难的不是让 Agent 跑起来，而是定义什么时候停、怎么验证。

视频讲了什么

主讲人安妮从模型基础讲起：预训练学语言与知识，后训练学会听指令，偏好优化/强化学习让输出更符合人类预期。但模型本身无状态，每次请求都只看当前上下文；产品层把历史、记忆、工作空间重新塞回去，才让用户觉得“它记得”。

接着是 Agent 的能力组件：工具调用让模型能查网页、读写文件；MCP 用统一协议连接外部系统，提供的不只是工具，还有资源与提示词模板；skill 承载一类任务的完整工作流；plugin 则是把 MCP、skill、规则、hooks 打包的产品层概念。

核心篇幅在上下文工程。上下文不是越多越好，无关内容会干扰判断。她总结了五个操作：写入、选择、检索、压缩、隔离——把目标/规则/环境写清楚，只选当前相关的内容，按需检索历史，满了就压缩，子 Agent 用独立上下文只回传结果。还讲了提示词缓存：中途换模型会让缓存失效，也可能触发压缩丢信息，所以一个会话尽量别频繁换模型。

记忆部分强调“准入判断”：聊天记录只说明发生过什么，不代表都该影响未来。系统提取语义记忆、用户知识、表达偏好、行为记忆、对话记忆，并控制作用域（当前轮/会话/工作空间/用户/团队）和过期、纠正、删除。

后半场是 harness engineering：引导、约束、整合三类能力，分五层——运行环境、前馈（动手前让模型知道什么）、反馈（做完怎么知道对错）、编排（工具/记忆/子 Agent 如何组织）、自我迭代。她对比了 OpenAI（三人五个月 100 万行代码、1500 个 PR）、Anthropic（规划/实现/验收三角色，独立验收降低自我评估偏乐观）、LangChain（模型与 harness 共同进化）的实践。

最后指出 harness 解决不了的事：业务正确性有验证缺口，模型理解错需求时，它写的测试也会跟着错；边界组合、同名技能作用域冲突仍需人介入。于是引出循环工程：回合式、目标式、定时、事件触发四类循环，关键是触发条件、任务状态、执行工具、验证标准、继续/停止条件与成本。

关键点

  • 模型无状态：记忆是产品层把历史与工作空间重新送入上下文的结果。
  • 工具/MCP/skill/plugin 分工：工具是一个动作，skill 是一类任务的工作流，plugin 是打包。
  • 上下文五操作：写入、选择、检索、压缩、隔离；目标是相关、准确、及时，不是堆 token。
  • 换模型有代价：缓存失效、可能触发压缩，一个会话尽量固定模型。
  • 记忆要准入：不是所有聊天记录都该长期保留，要控制作用域与过期。
  • harness 五层：运行环境、前馈、反馈、编排、自我迭代；安全边界必须落在环境层，不能只靠提示词。
  • 独立验收：实现与验收分开，能降低“自己觉得自己对了”的偏差。
  • 循环工程：难点在验证标准与停止条件，不在循环本身。
