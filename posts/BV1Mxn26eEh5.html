DeepSeek 开源推理框架 DeepInfer：P/D 分离与 KVCache 架构

一句话总结P/D 分离、KVCache 独立存储 72 小时、SWA 有界重放、DSpark 推测解码，96% 缓存命中背后的成本账。

一句话总结

这期是 DeepSeek 开源的内部推理框架 DeepInfer 的导读：重点不是逐行读代码，而是理解它为什么能把推理成本压下来——Prefill/Decode 分离、KVCache 独立集群与 72 小时保留、SWA 有界重放、DSpark 推测解码，以及 96% 缓存命中率背后的工程取舍。

视频讲了什么

DeepSeek 这次开源了两样东西：DeepInfer 框架本体，以及 deepseek-recipe 编解码组件。后者把 Claude Code 的 message、Codex 的 responses、常见 chat completions 三种请求统一转成 DeepSeek 内部提示词格式，再转成对应接口输出；技术难度不算高，但能省掉大量适配工作。开源的主要意义是：需要部署 DeepSeek 的团队可以直接参考它的推理框架，研究者和学者也能从里面吸收方法论。

核心是 P/D 分离。Prefill 是预填充：把提示词（包括 system prompt、工具说明、MCP 描述）一次性大规模并行计算，快速理解上下文；DeepSeek 统计的平均提示词长度是 77K token，已经占 256K 上下文的三成。Decode 是解码：从第一个输出 token 开始串行计算，每步都要回顾之前的 KVCache，效率天然低。把 Prefill 和 Decode 部署到不同硬件上，是为了避免两个阶段抢资源。

KVCache 这次被做成独立集群：不放在 GPU 显存里，而是单独存储，保留 72 小时；官方给出的缓存命中率约 96%。缓存命中直接决定成本和延迟：命中就走 Decode，不命中才进 Prefill。视频给的数据是 230 TPS，代码场景可到 300 TPS；官方还有一个 38 美元的成本数字，视频作者交叉计算后认为能对上。

降低注意力成本的关键是 SWA 有界重放：传统 attention 随上下文长度平方增长，有界重放把它变成线性增长，同时提升缓存命中率，两个优势叠加进一步降计算。另一个是 DSpark 推测解码：在 MTP 基础上做并行草稿器，多个草稿同时展开，覆盖更多候选；再用置信度调度决定「干得好就多干、干不好就收手」，并做验证。配合异步批调度（GPU 不必等 CPU）和固定随机种子下的批不变性/确定性输出，推理效率和可复现性一起拿。

最后是边界：DeepInfer 绑定 DeepSeek V4.1 Flash，构建在 vLLM/SGLang/TensorRT 之上，不是替代 vLLM；只支持 Linux + CUDA 13 + SM100（B100/B200/GB200）或昇腾 950，消费级显卡和 Windows 都跑不了。这次开源的边界也不包括 KVCache 系统、部署编排和副本负载均衡。

关键点

  • P/D 分离：Prefill 计算密集、Decode 访存密集，分到不同硬件避免互相抢资源。
  • KVCache 是成本中心：独立存储 + 72 小时保留 + 96% 命中，决定了首 token 延迟和整体吞吐。
  • SWA 有界重放：把 attention 从平方级压到线性级，同时提高缓存命中率。
  • DSpark：并行草稿 + 置信度调度 + 验证，用推测解码换吞吐。
  • 确定性输出：批不变性 + 固定随机种子，保证同样输入给同样结果。
  • 开源边界：框架和 recipe 开了，KVCache 系统/部署编排/副本负载均衡没开。

适合谁看
