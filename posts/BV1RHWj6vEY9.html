AgentBaton：强模型先做、小模型收尾，Agent 成本直降 65.9%

UP：熊二等兵 · BV1RHWj6vEY9 · 2026-11-11

一句话总结AgentBaton 让强模型先做长程任务核心，再由轻量检测器判断交接时机，把局部修复与收尾交给小模型；两个基准、11 组模型对平均降 65.9% API 成本，精度基本不降，部分组合更高。

一句话总结

这篇论文提出 AgentBaton：让强模型先做长程 Agent 任务的核心部分，再由一个轻量检测器判断“什么时候可以交接”，把剩下的局部修复、验证收尾交给便宜的小模型。结果是平均 API 成本降低 65.9%，精度基本不降，部分组合甚至更高。

视频讲了什么

视频解读的是论文《AgentBaton: Efficient Model Collaboration in Agentic Tasks》。它先点出矛盾：长周期 Agent 任务效果最好的一般是高端模型，但多轮调用很贵；小模型便宜，单独用准确率又不够。之前的多模型方案大多只做“单次查询级路由”，适配不了任务过程中不断变化的需求。

论文把问题拆成两个：切换方向（先弱后强，还是先强后弱）和上下文怎么传（直接塞历史，还是写日志让下一个模型自己查）。实验在 Terminal Bench 2.1 和 DeepSWE v1.1 上做，用强模型跑基线，再在轨迹的 30%、75% 等节点做一次交接、不回切。

结论很不对称：弱→强整体不如全程强模型，有时成本还更高；强→弱只要时机对，精度几乎不变，成本大幅下降。上下文传输也不是一种方式通吃：弱→强更适合日志文件，强→弱则要看原模型是否暴露完整思维链——暴露的用直接上下文更好，不暴露的用日志更好。

接着是切换时机。论文总结了三个“可以交接”的信号：已有可运行原型/核心产出；已经通过测试或检查、拿到具体反馈；剩下的是局部排查、修复、验证。哪怕反馈是负面的，只要问题范围缩小了，也可以交给小模型。

最后是 AgentBaton 检测器：用约 4000 条执行轨迹训练一个很小的模型，每轮判断“ready / not ready”，第一次 ready 就交接。单张 H100 上中位延迟约 338ms，不会明显拖慢任务。跨 11 组模型对、两个基准，平均省 65.9% API 成本，最高精度比全程强模型高 8.8 个百分点。

关键点

  • 核心范式：强模型先做规划/核心实现，合适时机一次性交给高效模型收尾。
  • 方向不对称：强→弱有效；弱→强往往不省钱，还可能错误累积。
  • 上下文迁移：日志文件适合弱→强；强→弱按原模型是否暴露思维链选择直接上下文或日志。
  • 三个交接信号：有可运行原型、拿到测试反馈、剩余工作已局部化。
  • 检测器：轻量分类器在线判断交接点，中位延迟 338ms，无需改现有 Agent 框架。
  • 收益：平均 -65.9% API 成本；11 组模型对中多数保持精度，部分还提升。
  • 局限：目前只支持一次交接，未来可探索多次切换和自适应上下文方式。
