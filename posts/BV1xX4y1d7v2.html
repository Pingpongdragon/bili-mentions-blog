信号量：袋子和球，从生产者消费者到哲学家吃饭

UP：绿导师原谅你了 · BV1xX4y1d7v2 · 2026-11-14

一句话总结信号量是带计数器的袋子：P 拿球、V 放球；初值 1 是互斥锁，初值 N 是并发限额。用它可写生产者消费者、happens-before 和计算图；哲学家吃饭可用限制上桌人数或集中服务员避免死锁。

一句话总结

这节从“信号量到底是什么”讲起：它就是一个带计数器的袋子，P 拿走一个球、V 放回一个球；初值为 1 时就是互斥锁，初值为 N 时可以控制并发数。掌握“袋子和球”的模型后，生产者消费者、happens-before、计算图、哲学家吃饭都能用同一套语言拆开。

视频讲了什么

开场先回顾条件变量：拿锁、检查条件、在锁内做操作；条件变量的问题是 signal 可能丢，且条件可以任意复杂。信号量是它的一个特例：内部只有一个 count，P 等到 count > 0 再减一，V 直接加一；因为带计数，V 不会像 signal 那样“没人等就丢掉”。

接着用“袋子/球”和“游泳池手环”两个比喻讲清楚：袋子代表资源池，球代表一单位许可；P 是伸手拿球，拿不到就等；V 是往袋子里放球。初值设为 1，P/V 就退化成 lock/unlock；初值设为 N，就能限制同时进入的线程数。

然后落到生产者消费者：一个信号量表示“还能打几个左括号”，初值 N；另一个表示“已经打了几个左括号、可以打几个右括号”，初值 0。打左括号前 P(empty)、打完后 V(fill)；打右括号前 P(fill)、打完后 V(empty)。两个袋子之间挪球，就把同步写出来了。

第三块是 happens-before：给“A 必须先于 B”建一个初值 0 的信号量，A 完成后 V，B 开始前 P。它比条件变量简单，因为计数不会丢。把每个依赖边都放一个信号量，就能实现任意计算图；线程 join 只是它的特例。若线程太多，可以把节点打包进一个线程，用程序顺序省掉部分同步。

最后是哲学家吃饭：最直接的写法是每把叉子一个信号量，先 P 左再 P 右；五人同时拿起左手叉子就会死锁。视频给了两种思路：限制同时上桌人数（如 4 人），或者引入“服务员”集中管理叉子——所有请求先发给服务员，由它决定谁吃、谁等。集中式牺牲一点分布性，但能做全局公平与调度；前提是服务员不成为瓶颈。

关键点

  • 信号量 = 计数器 + 等待：P 等 count>0 再减一，V 加一。
  • 初值 1 = 互斥锁：P 是 lock，V 是 unlock。
  • 初值 N = 并发限额：袋子里有 N 个球，第 N+1 个线程要等。
  • 生产者消费者：empty/fill 两个袋子互相挪球。
  • happens-before：初值 0 的信号量，A 完成 V、B 开始 P。
  • 计算图：每条依赖边一个信号量；join 是特例。
  • 哲学家死锁：五人同时拿左叉；限制上桌人数或集中服务员。
  • 集中式取舍：公平与全局调度更好，但服务员可能成瓶颈。
